## How work flows

Lightweight on purpose. Skip a step only when the team agrees it adds nothing for that change.

1. Work starts from a GitHub issue with acceptance criteria, in a sprint milestone, with a named owner.
2. Branch named after the issue (for example `fr-01-registration`).
3. Pull request that links the issue, reviewed by one teammate.
4. Typecheck and build pass, then merge to `main`.
