# Agile documentation

This folder holds the team's Scrum records for the BuilderWars platform. The course requires a product backlog, sprint planning summaries, scrum meeting summaries, sprint review feedback, and sprint retrospectives on GitHub.

## Files

- [`product-backlog.md`](product-backlog.md) — the backlog: GitHub issues by sprint, plus the migration and rebrand updates that are delivered inside those issues
- [`team.md`](team.md) — who is on the team and what each person is focusing on
- `sprint-N/` — one folder per sprint:
  - `planning.md` — sprint goal, committed issues, owners, decisions
  - `scrum-meetings.md` — one entry per meeting
  - `review.md` — what was demonstrated and the feedback received
  - `retrospective.md` — what went well, what didn't, what to change
  - `contributions.md` — added at the end of the sprint: each member's merged PRs, commits, and closed issues, as factual input for peer reviews

## How we use it

- The backlog lives in GitHub issues. Each sprint is a milestone.
- Record discussions, decisions, and feedback as they happen, in the sprint folder. Short and dated is better than complete and late.
- Claude helps draft these files from the team's notes and from GitHub activity. The content (what was said, decided, and agreed) comes from the team.
- Peer reviews are written by each student and submitted the way the course asks. They are not stored here. `contributions.md` exists only to give everyone the same facts to work from.
